# 返礼品管理ポータル（事業者向けスマホ管理システム）

ふるさと納税の返礼品を取り扱う事業者が、スマートフォンから簡単に以下の変更申請を行い、
その内容を Slack / Lark（自治体・運営担当者）へ自動送信するためのシステムです。
まずは **塩尻市で試験導入** することを想定しています。

## できること

### 事業者向けポータル（`/login.html` → `/portal.html`）
- ID・パスワードでログイン（自治体担当者が発行）。**一度ログインすれば以後パスワードは求められません**
  （既定180日のセッションを、利用のたびに自動延長します。`OPERATOR_SESSION_DAYS` で変更可）
- 自分が取り扱う返礼品一覧を表示（塩尻市マスタから抽出済み）
- 各返礼品ごとに、スマホでスクロール操作しながら以下を変更申請
  - **在庫調整**：増減数をスクロールで選択／受付「停止」「再開」をワンタップ
  - **商品代変更**：万円・百円の位をスクロールで選択
  - **変更希望日**：年・月・日をスクロールで選択（対応にお時間がかかる旨を明記）
  - **発送期間変更**：開始日・終了日をそれぞれ年月日スクロールで選択
  - **受付期間変更**：開始日・終了日をそれぞれ年月日スクロールで選択
- 送信すると **Slack / Lark に自動通知** され、**同時に塩尻市マスタへも自動反映** されます

### 塩尻市マスタへの自動反映

送信と同時に、塩尻市マスタ「返礼品マスタ」シートの該当行（P列の商品コードで特定）を更新します。

| 変更種別 | 更新する列 |
| --- | --- |
| 在庫調整（増減） | T列 在庫数 |
| 商品代変更 | Y列 精算額 |
| 発送期間変更 | AE列 発送開始日 / AF列 発送終了日 |
| 在庫の停止・再開 | （対応列がないため備考のみ） |
| 変更希望日 / 受付期間変更 | （対応列がないため備考のみ） |

- 更新したセルは **背景を黄色に塗りつぶし** ます
- **C列の備考欄** に「更新前の値 → 更新後の値」と、誰が何を変更したかを追記します
  - 例: `[2026/8/22 14:03:11] 株式会社ベジサコ がポータルから変更 / 在庫数: 50 → 40`

対象シート: `MASTER_SPREADSHEET_ID` / `MASTER_SHEET_GID`（既定で塩尻市マスタの返礼品マスタ）。

### 管理画面（`/admin.html`）
- 自治体担当者が管理者パスワードでログイン
- **塩尻市マスタ（Googleスプレッドシート）から直接同期**、または xlsx / csv ファイルをアップロード
- 対象事業者の取り扱い返礼品のみを自動抽出（下記スコープ参照）
- 新規事業者には **ログイン用ID・パスワードを自動発行**（表示は発行時の一度きり）
- 事業者一覧・返礼品件数の確認、パスワード再発行、アカウント停止/再開

### 試験導入のスコープ（青果物・米）

**返礼品名から対象事業者を自動抽出** します。事業者名を事前に列挙する必要はありません
（対象カテゴリの返礼品を1件以上持つ事業者が、自動的に対象事業者になります）。

対象カテゴリ:
- りんご（サンふじ、シナノゴールド、シナノスイート、ぐんま名月、秋映 等）
- ぶどう（シャインマスカット、クイーンルージュ、ナガノパープル、巨峰、ピオーネ、デラウェア 等）
- 梨（南水、幸水、豊水 等）、桃・その他果物
- 野菜（長芋、トマト、きのこ 等）
- 米（コシヒカリ、風さやか、白米、玄米、無洗米 等）

**加工品は自動的に除外** します。返礼品名にカテゴリ名を含んでいても、青果物ではないためです。

| 除外される例 | 理由 |
| --- | --- |
| 信州りんごジュース / りんごチップ | 加工品 |
| 純米大吟醸 / マスカット・ベーリーA ワイン | 酒類・ワイン用品種 |
| りんご和牛 信州牛ロース | 精肉（ブランド名に果物名を含む） |
| 信州山芋そば 乾麺 | 麺類 |

調整は環境変数で行えます（コード変更不要）。

- `TARGET_PRODUCT_KEYWORDS`: 対象カテゴリのキーワード
- `EXCLUDE_PRODUCT_KEYWORDS`: 除外する加工品のキーワード
- `TARGET_OPERATORS`: 対象事業者を明示的に限定したい場合のみ設定

アカウント発行前に、管理画面の **「抽出結果を確認する」** で対象事業者・返礼品の一覧を
プレビューできます（`GET /api/admin/preview-master`）。

## 受付終了前の毎日リマインド

**先行予約・期間限定の返礼品**（＝発送期間に記載のある返礼品）について、
**受付終了日の1週間前から受付終了日当日まで、毎日リストにして通知** します。

目的:
- 翌年の受付開始の準備をするため
- 事業者へ再掲載受付の承諾を得るため

通知内容: 返礼品名・商品コード / 事業者名 / 受付終了日と残り日数 / 発送期間

発送期間の記載がない通年商品は、先行予約・期間限定ではないため通知対象外です。
対象が0件の日は通知しません。

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `REMINDER_LEAD_DAYS` | `7` | 受付終了日の何日前から通知するか |
| `REMINDER_HOUR_JST` | `9` | 毎日の通知時刻（日本時間） |
| `REMINDER_ENABLED` | `true` | `false` で無効化 |

確認用エンドポイント:
- `GET /api/admin/expiring?today=YYYY-MM-DD` — 対象一覧を表示（送信しない）
- `POST /api/admin/send-reminder` — 手動で送信

マスタファイルの列見出しの対応表・サンプルは [`docs/sample_master_template.csv`](docs/sample_master_template.csv) を参照してください。

## セットアップ

```bash
cd server
npm install
cp .env.example .env
# .env を編集: JWT_SECRET, ADMIN_PASSWORD, 通知先(SLACK_BOT_TOKEN 等)を設定
npm start
```

ブラウザで `http://localhost:3000` を開くと事業者ログイン画面が表示されます。
管理画面は `http://localhost:3000/admin.html` です。

## 設定が必要な認証情報

以下2つは運用開始前に設定が必要です。未設定の場合はその処理をスキップし、ログに警告を出すだけなので、
設定前でも画面の動作確認はできます。

### 1. 通知（Slack / Lark）

`NOTIFY_CHANNELS` で送信先を選びます（カンマ区切りで併用可）。

| 値 | 送信先 |
| --- | --- |
| `slack` （既定） | Slackのチャンネル、または担当者へのDM |
| `lark` | Larkのグループ（Webhook）、または担当者へのDM（アプリ） |
| `lark,slack` | 両方へ同じ内容を送信 |

**現在 Lark は組織のネットワークポリシーで遮断されています。**
`njpeyw9zsu29.jp.larksuite.com` / `open.larksuite.com` / `open.feishu.cn` のいずれも
プロキシが CONNECT に 403 を返すため到達できません。そのため既定を `slack` にしています。
Larkのドメインが許可され次第、`NOTIFY_CHANNELS=lark` に変えるだけで切り替わります（コード変更は不要）。

**Slack** — `chat:write` スコープを持つBotトークンを発行して設定します。

```
NOTIFY_CHANNELS=slack
SLACK_BOT_TOKEN=xoxb-...
SLACK_CHANNEL_ID=U0AGK5Z6BBL   # チャンネルID、またはDM相手のユーザーID
```

**Lark・試験運用（担当者宛にDM）** — `LARK_MODE=app`

1. [Lark開発者コンソール](https://open.larksuite.com/app) でアプリを作成
2. 権限に `im:message`（メッセージ送信）を追加して公開・承認
3. `.env` に設定
   - `LARK_APP_ID` / `LARK_APP_SECRET`
   - `LARK_RECEIVE_ID`: 送信先（既定はメールアドレス指定）
   - `LARK_RECEIVE_ID_TYPE`: `email` / `open_id` / `user_id`

**本番運用（塩尻市のLarkグループへ）** — `LARK_MODE=webhook`

1. 塩尻市のLarkグループに「カスタムボット」を追加し、Webhook URL を発行
2. `.env` の `LARK_WEBHOOK_URL`（必要なら `LARK_WEBHOOK_SECRET`）に設定し、`LARK_MODE=webhook` に変更

通知には、自治体名 / 事業者名・ID / 返礼品名・コード / 変更種別 / **変更前・変更後** /
**塩尻市マスタへの反映結果** / 申請日時 が含まれます。

### 2. 塩尻市マスタ（Googleスプレッドシート）への書き込み

1. Google Cloud でサービスアカウントを作成し、JSONキーを発行
2. Google Sheets API を有効化
3. **サービスアカウントのメールアドレスに、塩尻市マスタの「編集者」権限を付与**
4. JSONキーの内容を1行にして `.env` の `GOOGLE_SERVICE_ACCOUNT_JSON` に設定

## 既知のセキュリティ上の注意

マスタ取込（xlsx解析）には `xlsx` (SheetJS) パッケージを利用していますが、npm公開版には
既知の脆弱性（ReDoS・プロトタイプ汚染、GHSA-4r6h-8v6p-xvw6 / GHSA-5pgg-2g8v-p4x9）があり、
現時点でnpm経由の修正版はありません。本システムでは以下で影響を限定しています。

- マスタ取込 (`/api/admin/import-master`) は管理者ログイン必須（`requireAdminAuth`）
- アップロードできるのは自治体担当者などの信頼できる利用者のみを想定
- ファイルサイズ上限 20MB
- 可能であれば [SheetJS公式CDN](https://cdn.sheetjs.com) から修正済みバージョンを取得し、
  `server/package.json` の `xlsx` の依存を差し替えることを推奨します
  （本環境ではCDNへのアクセスが制限されていたため未反映です）

## データの扱いについて

事業者が送信すると、塩尻市マスタへ**即時反映**されます。更新箇所は黄色で塗りつぶし、
C列の備考に更新前の値が残るため、担当者は後から変更履歴を追え、必要なら元の値に戻せます。

なお、受付期間・変更希望日は返礼品マスタに対応する列がないため、C列の備考への記録と
通知のみを行い、実際の反映は担当者の対応となります。

## ディレクトリ構成

```
server/            Node.js (Express) API サーバー
  src/
    routes/         認証・事業者用・管理用の各API
    utils/          マスタ取込・パスワード発行ユーティリティ
    notify.js       Slack / Lark への通知送信
    db.js           JSONファイルベースの簡易DB
  data/             実行時に生成されるデータ（.gitignore対象）
web/                フロントエンド（静的ファイル、ビルド不要）
  js/scrollPicker.js  スクロール式の年月日・数量ホイールピッカー
  login.html / portal.html / admin.html
docs/               マスタ取込用サンプルCSV
```
